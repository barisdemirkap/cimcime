## Findings

### Refactoring UI (source: refactoringui.com landing page only)

Note: this is the sales page, so these are chapter-level topics, not the book's full arguments.

- Pitch: tactical design advice for developers rather than abstract theory. Book is 218 pages, 50 chapters, nine sections; also video walkthroughs (complex form, dashboard, text-heavy landing page), a component gallery (200+ ideas, no CSS), color palettes (10 shades per color), font suggestions (30+), and 200 SVG icons.
- Starting out: design around features first, pick a visual personality, limit options.
- Hierarchy: not everything deserves equal emphasis; de-emphasize secondary elements to make primary ones stand out; labels are a last resort.
- Layout and spacing: start with generous white space, define a spacing and sizing system, avoid ambiguous spacing.
- Text: use a type scale, readable fonts, controlled line length, line-height proportional to font size.
- Color: use HSL over hex, use more colors than expected, define shades up front, never rely on color alone for meaning.
- Depth: consistent light source, shadows convey elevation, consider two-part shadows.
- Images: good photos, consistent text contrast over images.
- Finishing touches: better defaults, accent borders, decorated backgrounds, empty states, fewer borders.
- Design-system relevance: the recurring idea is constraint by predefined scales (spacing, type, color shades, shadows), which is the seed of a design system.
