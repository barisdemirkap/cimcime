## Findings

**Typical starting points** (fde.academy): software engineers, DevOps/infrastructure engineers,
data engineers, ML engineers, and backend platform engineers — no single required pathway, but a
consistent requirement of **prior production experience** (typically 2-5 years) before
transitioning in.

**A concrete 9-step progression** (fde.academy): build foundational engineering skills → gain
production experience → learn system integration → develop AI/data expertise → work real
deployment projects → cultivate customer-facing skills → build a portfolio demonstrating real
integrations/outcomes → prepare for FDE-specific interviews → apply. Accelerants named:
startup roles, DevOps teams, enterprise implementation projects, or structured FDE training
programs.

**Two specific lateral paths, with a concrete learning plan** (bigtechcareers.com) — for
**Solutions Architects**: your customer-ecosystem discovery skill already *is* "use case
discovery" in AI; add LLM fundamentals, RAG architecture, and cost/latency tradeoffs. For
**Software Engineers**: your production experience already *is* the hard part; add LLM APIs,
vector databases, deployment patterns, AI observability. A concrete 5-8 week path: LLM
foundations + a simple chatbot → RAG/embeddings/vector-DB deep dive → agent frameworks and
customer-handoff practices → package into interview-ready case studies. The source's framing is
worth keeping verbatim: "The best AI FDEs are SA/SWE hybrids who learned the fundamentals of AI"
— the transition is explicitly a **lateral move**, not a restart, because debugging production
issues, stakeholder management, and shipping under constraints are the *primary* differentiators,
with AI knowledge as the addition, not the foundation.

**What FDE interviews specifically test** (sundeepteki.org), distinct from a standard SWE
interview: problem decomposition is the most heavily weighted skill — understanding customer
constraints before proposing a technical approach, not jumping to a solution; coding sits at
LeetCode-medium but framed in customer scenarios, not abstract puzzles (Python fluency required
for AI-focused roles); system design explicitly covers VPC deployment, SSO integration, HIPAA/
SOC2-style compliance, and legacy-system integration — not generic scalability design; behavioral
answers must show "end-to-end ownership," not "contribution to a team effort"; and — a sharp,
concrete point — company-specific values interviews differ meaningfully (Palantir: mission
alignment; OpenAI: intensity/scale; Anthropic: AI-safety considerations), and "generic SWE prep is
most dangerous" exactly there, since technical excellence alone doesn't overcome a values
mismatch.
