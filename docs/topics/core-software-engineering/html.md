## Findings

**What HTML is, converging across all three sources**: the standard markup language defining
structure/meaning of web content — "Hypertext" (linked text connecting pages) + "Markup"
(tags annotating content) + "Language" (a system the browser interprets). MDN: HTML provides
structure; CSS handles presentation; JavaScript handles behavior — the classic three-layer web
stack, named identically across roadmap.sh and freeCodeCamp.

**Best analogy found in this topic** (freeCodeCamp): "HTML is the skeleton, CSS is the skin,
and JavaScript is the circulatory, digestive, and respiratory systems" — also compared to house
construction (structure/aesthetics/functionality). A genuinely useful, concrete mental model,
not a generic restatement.

**MDN's documentation structure**: reference (128+ documented elements, global/element-specific
attributes) + guides (responsive images, forms/validation, microdata) + how-to articles + beginner
tutorials — the same beginner→guide→reference progression pattern already seen in `javascript.md`.

**Modern practice emphasis** (freeCodeCamp): semantic tags (`<header>`, `<nav>`, `<section>`,
`<footer>`) are now favored over generic `<div>`/`<span>` for accessibility and SEO — a concrete,
actionable best practice, not just historical trivia.

**Direct relevance to this system**: minimal — this project has no HTML/frontend surface. This
topic is pure background for a hypothetical future client-facing deliverable, consistent with
`learn-a-programming-language.md`'s framing that frontend skills let an FDE "deliver end-to-end
demos and prototypes without a separate frontend team."
